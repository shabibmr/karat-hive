# Node.js monolith over PostgreSQL

The backend is a single Node.js deployable with PostgreSQL as the only system of record. Identity, requests, offers, connections, admin, notifications, and the scheduled workers (fan-out, expiry sweeps, gold-rate polling, media processing) all live in one process boundary. Module separation is enforced in code, not over the network. Prescribed by `docs/Requirements-raw.txt` L99–L101; recorded as constraints C-11 and C-12.

**Why.** The two hardest invariants in this product are both easier in a monolith. Identity masking (`FR-SYS-003`, `NFR-013`) is enforced in **one** response-serialisation layer, so there is a single place to audit and a single place to test — in a service mesh the same rule would have to be replicated and kept consistent across every service that ever returns a Customer or Vendor. Offer acceptance (`FR-SYS-007`) accepts one Offer, rejects the competing Offers, creates the Connection, and reveals identities; as a single PostgreSQL transaction this is plain ACID, whereas across services it needs sagas and compensating actions for a flow that must never half-complete.

**Consequences.** The unit of scale is the whole application: capacity comes from running more identical instances behind a load balancer (`NFR-007`). That requires no state in process memory — sessions, caches, and idempotency keys live in PostgreSQL (`NFR-009`) — and database-backed locks so scheduled jobs do not double-fire across instances. Background load and interactive load share a process, so worker execution must be togglable per instance to protect API latency. One database means one failure domain: PITR and tested restores are not optional (`NFR-011`).

**Considered options.** Microservices from day one (rejected: distributed transactions and replicated masking rules for a team and traffic profile that need neither); serverless functions (rejected: connection-pool pressure on PostgreSQL, cold starts against the `NFR-001` latency budget, and awkward long-running media processing); a separate worker service (deferred — the toggle in `NFR-009` gets most of the benefit without a second deployable).
