What this is

Static HTML/CSS/JS mock of all 67 inventory screens (22 Customer · 22 Vendor · 23 Admin). Hardcoded sample data. No backend.

  • Customer & Vendor: mobile phone shell
  • Admin: web layout with sidebar
  • Visual system from design context (sapphire + metallic gold)

How to run

Must use HTTP (partials load via fetch):

npx --yes serve ui-mock

Or python -m http.server from ui-mock/.

Login

Role chooser only — Customer / Vendor / Admin. No password.

Full auth fields still appear on CUS-S01, VEN-S01/S04, ADM-S01 (open via Screen map ☰).

Navigation

  • Routes: #/customer/CUS-S02, #/vendor/VEN-S05, #/admin/ADM-S02
  • Customer tabs: Home · Requests · Connections · Alerts · Profile
  • Vendor tabs: Home · Requests · Offers · Connect · More
  • ☰ Screen map = every screen for current role
  • Screen ID pill (e.g. CUS-S02) always visible in chrome

Product flow

  1. Customer creates a Request
  2. Vendors get matched → submit Offers
  3. Customer compares → Mark as Interested
  4. Identities reveal → WhatsApp Talk
  5. Optional reviews

Until accept: masked labels only (BR-006). After: real name, phone, business on Connection screens.

Design notes

  • Warm ivory canvas, crystalline glass cards, slate obsidian text, restrained gold
  • Gold-light sweep on heroes/CTAs (disabled if reduced motion)
  • WhatsApp green only on Talk buttons
  • Status = chip + text, not colour alone

Field completeness

Each screen HTML is built from the matching ui-screens/**/*.md Fields table. Labels match inventory names; values are sample.

Suggested path: Customer Home → create → offers → accept → connection → switch Vendor → Admin queues.
